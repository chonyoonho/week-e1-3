# MAC 기반 패턴 판정기 (Cross / X)

패턴(2차원 숫자 배열)이 **Cross(+)** 필터와 **X** 필터 중 어느 쪽과 더 닮았는지 **MAC(Multiply-Accumulate) 점수**로 판정하는 Python 콘솔 애플리케이션입니다. NumPy 등 외부 라이브러리 없이 반복문으로 직접 구현했습니다.

## 1. 실행 방법

```bash
python main.py              # 같은 폴더의 data.json 사용
python main.py other.json   # 다른 JSON 파일 지정
```

- Python 3.8 이상, 표준 라이브러리만 사용
- 실행하면 입력 방식을 선택합니다.
  - `1` 사용자 입력(3×3): 필터 A, B와 패턴을 한 줄씩(공백 구분) 입력
  - `2` data.json 분석: 5×5, 13×13, 25×25 케이스를 일괄 판정

## 2. 파일 구성

| 파일 | 설명 |
|---|---|
| `main.py` | 프로그램 전체 (단일 파일) |
| `data.json` | 테스트용 샘플 데이터 (정상 12건). **제출 시 과제에서 제공된 data.json으로 교체** |
| `data_error_demo.json` | FAIL 처리 시연용 데이터 (실패 유형별 8건) |
| `README.md` | 이 문서 |

## 3. 코드 구조

| 구분 | 함수/클래스 | 역할 |
|---|---|---|
| 데이터 구조 | `Matrix` | n×n 배열 저장, `get(r, c)` / `set(r, c, v)` |
| 핵심 로직 | `mac` | 같은 위치끼리 곱해 모두 더함 (이중 반복문, O(N²)) |
| | `compare_scores` / `judge_scores` | epsilon 기반 동점 처리 후 Cross / X / UNDECIDED 판정 |
| | `normalize_label` | `'+'`, `'cross'` → Cross, `'x'` → X |
| 성능 | `measure_mac_time` | MAC만 10회 반복 측정해 평균(ms) 계산 (I/O 제외) |
| 모드 1 | `read_matrix`, `run_user_mode` | 입력 검증, 재입력 유도, 점수·시간·판정 출력 |
| 모드 2 | `load_filters`, `evaluate_case`, `run_json_mode` | 스키마 검증, 필터 선택, 판정, PASS/FAIL, 요약 |

## 4. data.json 구조 (가정)

```json
{
  "filters":  { "size_5": { "cross": [[...]], "x": [[...]] }, "size_13": {...}, "size_25": {...} },
  "patterns": { "size_5_1": { "input": [[...]], "expected": "+" }, ... }
}
```

- 패턴 키 `size_{N}_{idx}`에서 N을 뽑아 `filters.size_N`을 선택합니다.
- 패턴과 필터의 크기가 다르면 **그 케이스만 FAIL**로 기록하고 프로그램은 계속 진행합니다.
- 파일이 없거나 JSON 형식이 깨졌을 때도 오류 메시지만 출력하고 정상 종료합니다.

## 5. 설계 정책

- **라벨 정규화:** 내부 표준 라벨은 `Cross`, `X` 두 가지입니다. expected `'+'`/`'x'`와 필터 키 `'cross'`/`'x'`를 모두 표준 라벨로 바꾼 뒤 비교하고 출력합니다. 대소문자와 앞뒤 공백도 무시합니다.
- **점수 비교(epsilon):** `abs(score_a - score_b) < 1e-9`이면 동점으로 봅니다. 동점은 `UNDECIDED`(모드 1에서는 "판정 불가")이며, expected와 같을 수 없으므로 FAIL입니다.
- **실패 원인 분류:** 모든 FAIL에 `데이터/스키마`, `로직(판정 불일치)`, `수치 비교(동점)` 중 하나의 분류를 붙여 요약에 표시합니다.

## 7. 결과 리포트

> ※ 아래 수치는 샘플 data.json과 개발 환경에서 측정한 값입니다. **제출 전에 본인 PC에서 실행한 결과와 과제용 data.json 결과로 교체하세요.**

### 7-1. 성능 분석 표 (각 크기 10회 반복 평균)

| 크기(N×N) | 평균 시간(ms) | 연산 횟수(N²) |
|---|---|---|
| 3×3 | 0.000570 | 9 |
| 5×5 | 0.001092 | 25 |
| 13×13 | 0.004861 | 169 |
| 25×25 | 0.014258 | 625 |

### 7-2. 실패 원인 분석

1. 샘플 data.json 12건은 **실패 0건**이었습니다. 실패가 없었던 이유는 아래 두 정책 덕분입니다.
2. 첫째, **라벨 정규화**입니다. expected는 `'+'`/`'x'`, 필터 키는 `'cross'`/`'x'`로 표기가 달라서, 그대로 문자열 비교하면 정답인데도 FAIL이 납니다. 비교 전에 모두 `Cross`/`X`로 통일해서 이 문제를 막았습니다.
3. 둘째, **epsilon 비교**입니다. 점수를 `==`로 비교하면 `0.1 + 0.2 == 0.3`이 `False`가 되는 것처럼 부동소수점 오차 때문에 같은 값이 다르게 보일 수 있습니다. `abs(a - b) < 1e-9`를 동점 기준으로 써서 이 문제를 막았습니다.
4. 실패가 생길 수 있는 경우는 오류 데모 파일로 확인했고, 원인을 세 가지로 나눠 진단했습니다.
5. **데이터/스키마 문제:** 패턴 크기와 필터 크기 불일치(`size_5_2`), 정규화할 수 없는 expected 라벨(`size_5_3`), 숫자가 아닌 값(`size_5_5`), 필터 없음(`size_7_1`), 키 형식 오류(`bad_key`). 이런 경우는 점수를 계산하기 전에 걸러내고, 사유를 남긴 뒤 다음 케이스로 넘어갑니다.
6. **수치 비교 문제:** 모든 칸이 1인 패턴은 Cross=9, X=9로 점수가 같아 `UNDECIDED`가 됩니다(`size_5_4`). 필터가 두 라벨을 구분하지 못하는 입력이므로 FAIL이 맞는 결과입니다.
7. **로직 문제:** 점수와 판정은 정상인데 expected와 다른 경우입니다(`size_5_6`). 먼저 데이터의 expected가 틀렸는지 확인하고, 데이터가 맞다면 MAC이나 판정 코드를 의심합니다.
8. 진단 순서는 "스키마·라벨 검사 → 크기 검사 → 점수 비교(동점 여부) → expected 비교"입니다. 앞 단계에서 원인이 걸러지므로 로직 문제와 데이터 문제가 섞이지 않습니다.
9. MAC 구현은 난수 행렬 300쌍을 `sum(zip)` 방식의 독립 계산과 비교해 일치함을 확인했습니다.
10. 한계: 샘플 데이터는 0/1 값만 쓴 이상적인 모양이라 점수 차이가 큽니다. 실제 data.json에 소수 값이나 노이즈가 많으면 동점 처리 기준(epsilon 크기)을 다시 검토해야 합니다.

### 7-3. 시간 복잡도 분석

1. `mac`은 N개의 행마다 N개의 열을 도는 **이중 반복문**이라 곱셈·덧셈이 N×N번 일어납니다. 따라서 시간 복잡도는 **O(N²)**입니다.
2. 연산 횟수는 3×3은 9번, 5×5는 25번, 13×13은 169번, 25×25는 625번입니다. 한 변이 2배가 되면 연산 횟수는 4배가 됩니다.
3. 3×3에서 25×25로 가면 연산 횟수는 69.4배인데, 측정 시간은 약 25배만 늘었습니다. 크기가 작을 때는 함수 호출, 행 접근, 타이머 오버헤드 같은 **고정 비용**이 전체 시간의 큰 부분을 차지하기 때문입니다.
4. 이 고정 비용이 가려지는 큰 크기로 따로 측정하면 시간이 연산 횟수와 거의 같은 비율로 늘어납니다(참고 측정).

| N | 평균 시간(ms) | 연산 횟수 | 시간 증가 배율 | 연산 횟수 증가 배율 |
|---|---|---|---|---|
| 25 | 0.0277 | 625 | - | - |
| 50 | 0.0965 | 2,500 | 3.48 | 4.00 |
| 100 | 0.3854 | 10,000 | 3.99 | 4.00 |
| 200 | 1.4828 | 40,000 | 3.85 | 4.00 |

5. N이 2배가 될 때마다 시간이 약 4배가 되므로 측정 결과가 O(N²)와 맞습니다.
6. 필터 2개를 비교하면 MAC을 2번 호출하므로 총 시간은 2배가 되지만, 상수 배수라서 O(N²)라는 점은 같습니다.
7. 패턴 개수를 K라 하면 data.json 전체 처리는 O(K·N²)입니다.
8. 실무에서는 N이 커질수록 이 계산을 GPU/NPU 같은 하드웨어로 병렬 처리하는 이유가 여기에 있습니다.
